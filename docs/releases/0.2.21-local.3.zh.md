# 0.2.21-local.3 — 修复客户端启动阻塞

## 问题

在 DSH NEXT 0.2.1-rc.2 启用上一版本并重启后，Web 客户端报告：

```text
web boot: 1 entry did not activate
@shuind/dsh-codex-harness: pending (waiting for service: settingsScope)
```

当前宿主提供 `configForms`，已无旧 `settingsScope` 服务或 `dsh-client-runtime` 模块。上一版本的测试使用旧服务模拟对象，因此未覆盖实际宿主服务集合。

## 修复

- 客户端依赖改为 `configForms`，使用 `get('codex')` 取得宿主管理的共享设置控制器。
- 删除客户端加载清单中已不存在的 `dsh-client-runtime`。
- 设置控制器使用与实际宿主接口一致的窄结构类型；设置动作等待宿主写入完成，保留异常传播。
- 最低宿主版本声明对齐本次验证的 DSH 0.2.1-rc.2。
- 真实 Cordis 启动回归只提供 `configForms`，明确不提供 `settingsScope`；验证插件激活、设置卡片挂载、快照订阅和设置写入。

## 验证

15 个测试文件、152 项测试通过；严格 TypeScript 检查通过；后端及浏览器客户端构建通过。还核对了打包宿主官方设置客户端中的 `configForms.get(namespace)` 实现和其余服务名称。

本版本修复服务依赖导致的启动阻塞。安装后需重启应用加载新的客户端包；未进行真实模型调用。
