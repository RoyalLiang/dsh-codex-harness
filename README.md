# DSH Codex Harness

[English](README.en.md)

为 DeepSeek Harness（DSH）提供 Codex 风格的编码代理预设、输入栏控件和 token 用量诊断。复用宿主的工具、权限和任务生命周期，帮助代理控制上下文、保留任务进度并验证执行结果。

## 功能

- **Codex 模式**：提供编码协作策略，覆盖范围检查、验证、后台任务跟踪和压缩后的任务衔接。
- **上下文管理**：大工具结果保留精简预览和原文读取路径；摘要请求使用独立输出预算。
- **Fast 开关**：为受支持的 GPT Responses 请求附加优先服务参数，配置实时生效。
- **推理等级**：按模型公开能力提供选项；已有会话选择保留，未设置时优先使用 High。
- **用量诊断**：报告最近调用、累计 token 和按对话、压缩、标题用途分组的统计。

## 安装

### 环境要求

- Node.js **24 或更新版本**。
- 提供 `dsh-tools 0.2.1-rc.2` 或 `0.2.1-rc.3`、`schemastery ^3.0.0` 的兼容 DSH 宿主。
- 模型与服务提供商由宿主配置；插件不包含模型账号或凭据。

### 桌面应用

1. 获取插件的 `.tgz` 安装包。也可在源码目录运行 `npm pack --ignore-scripts`，使用命令输出的文件名定位安装包。
2. 通过 DSH 桌面应用的插件管理器安装该文件。
3. 重启宿主，创建新会话并选择 **Codex 模式**。

桌面的 `desktop` profile 由应用管理，请通过插件管理器安装。已有会话不会自动切换预设。发行变更见 [发行说明](RELEASE_NOTES.md)。

### CLI profile

对于非桌面管理的 profile，可替换下面的 profile 名和安装包绝对路径：

```sh
dsh plugin --profile my-profile add file:/absolute/path/plugin.tgz --ignore-scripts
```

## 使用

在输入栏切换 Fast 或选择推理等级，设置从后续请求开始生效。Fast 是插件全局配置，推理选择按当前会话和模型保存。

- **Fast**：只为 `gpt-*` 模型的 Responses 请求附加 `service_tier: "priority"`。服务端是否接受、如何计费由提供商决定。
- **推理等级**：仅模型明确支持的选项会提交给宿主。缺少能力元数据时，列表只保存本地偏好，不改变模型请求；界面提示会说明该限制。
- **状态查询**：让代理调用只读工具 `codex_harness_status`，查看控制项是否受支持以及实际用量。缺失数据保持 `null`。

工具执行、权限、审批、取消和子代理调度仍由宿主管理。插件策略不会赋予额外权限，取消操作也不会撤销已经发生的修改。

## 配置

在宿主插件设置中修改以下字段。使用推理选择器时，建议保留 `reasoningEffort: inherit`。

| 字段 | 默认值 | 作用 |
| --- | --- | --- |
| `enabled` | `true` | 启用请求适配、行为策略和用量观测。 |
| `fast` | `false` | 为适用的请求启用优先服务参数。 |
| `reasoningEffort` | `inherit` | 继承宿主设置；其他值只在模型明确支持时覆盖。 |
| `contextWindow` | `0` | `0` 表示继承。当前公开接口不支持覆盖窗口，正数会报告 `unsupported-public-api`。 |
| `instructions` | 空字符串 | 向内置行为策略追加说明。 |

### 上下文预算

Codex 模式通过宿主预设子插件配置以下预算，它们不属于上表中的字段：

| 配置 | 预算 | 行为 |
| --- | --- | --- |
| 工具结果预览 | 4,096 个估算 token | 结果进入历史前保留首尾预览和原文路径。 |
| 摘要请求输出 | 16,384 tokens | 限制单次摘要输出，包含提供商计入的推理 tokens。 |

`read` 不受这条预览策略裁剪，可按范围读取原文。预览可能包含多级恢复路径；存储失败或图片无法可靠计价、恢复时保留原结果，因此预算不是所有结果的硬上限。工具自身已丢弃的内容无法找回。

压缩触发阈值和近期历史保留预算沿用宿主设置。截断摘要会被宿主拒绝；若真实模型经常达到摘要上限，应提高该预设子插件的预算。关闭插件的 `enabled` 不会撤销预设组合中的预算配置。

## 用量与缓存统计

`codex_harness_status` 返回 `controls`、`usage`、`totals` 和 `byPurpose`，仅在调用时输出，不向每次模型请求追加统计消息。

- DSH 的未缓存输入、缓存读取和缓存写入是独立计数，总输入为三者之和。
- 累计命中率按累计 token 加权；字段缺失、无效或溢出时保持未知，不伪造零用量。
- 推理 token 单独报告，不重复加到输出或总量。流只采用最后一份 usage；失败和提前关闭也记录调用。
- 统计仅保存在进程内，最多保留 128 个活跃会话。会话销毁、插件卸载或进程重启后清理；已淘汰或销毁会话的晚到流不会恢复旧统计。

这些数据不是完整账单，不汇总子代理会话，也不估算费用。文本估算的缩减不能直接视为实际 token 或费用节省。

## 开发与测试

在源码目录安装依赖并运行检查：

```sh
npm ci
npm test
npm run check
```

普通测试覆盖用量累计、配置、输入栏控件、Fast 请求适配和宿主生命周期。

可选宿主场景测试需要兼容宿主包。将 `DSH_CONTEXT_HOST_ROOT` 指向含 `node_modules` 的目录，再运行测试。例如在 PowerShell 中：

```powershell
$env:DSH_CONTEXT_HOST_ROOT = 'C:\path\to\host'
npm test
```

该目录需提供 `dsh-spill-policy`、`dsh-spill-local`、`dsh-token-meter`、`dsh-compaction-basic`、`dsh-compaction-tool-result-pruner`、它们的依赖及 `yaml`。未设置变量时明确跳过场景组；设置后缺包会失败。场景覆盖日志恢复、隔离、失败回退、取消、图片保留和摘要截断；脚本模型流不代表真实模型的任务恢复质量测试。
